# Managed direct-stream internal beta

Implementation is not live provider verification. Public admission is intentionally absent. `MANAGED_INTERNAL_BETA=false` is the default; admission also requires an explicit internal billing-account UUID allowlist, matching database project/region binding, working regional provider credentials, recent successful API checks, eligible funds and no unresolved review alerts.

## Admission and accounting

Authenticated `/stream/admit` accepts only a request UUID. Existing Supabase verification derives the billing account. A transaction takes the existing billing lock plus the account row lock, allocates expiration-first reservations against original grant IDs, and persists the lease before calling Soniox. Reservations reduce available time but are not ledger debits. Current implementation serializes billing writes globally as well as per account; scaling this requires a lock-order review.

Temporary credentials request `usage_type=transcribe_websocket`, `single_use=true`, a 30-second admission expiry, a server UUID reference and funded `max_session_duration_seconds` (default maximum 1800; provider maximum 18000). Only trusted Electron main receives the key, retains it in memory, and connects to the fixed regional endpoint. Audio and text travel directly between desktop and Soniox. The renderer never receives either company or temporary keys. Personal mode bypasses this admission boundary and the managed ledger.

Retries of the same request return its existing status, never another key. A timeout remains uncertain and fully reserved. Three admissions per minute per account are the maximum; at most two unresolved credentials are allowed. A second stream cannot start before a provider completion record or the first lease's conservative new-admission-plus-duration boundary. Stop, a socket close, heartbeat, and process exit are not authoritative settlement evidence. Missing records retain reservations. The app shows usage finalizing and does not treat absence as zero usage.

Usage is verified `input_audio_duration_ms`, including transmitted silence. No multiplication by channels or translation output occurs. Integer milliseconds are debited once, against original reservation buckets even if reconciliation happens after expiry. Unused expired funds do not roll over. The stream is bounded before the earliest funding expiry, with a 60-second admission/clock margin. Hosts require synchronized clocks; this margin is not a provider guarantee. Provider costs remain decimal strings / PostgreSQL numeric(30,10); comparisons use scaled BigInt. Overruns debit the original bucket, may make it negative, and block new admission for review instead of spending a later grant.

Reconciliation persists the exact end-time window and pagination cursor, overlaps at least 48 hours, revisits unresolved leases up to 30 days, and deduplicates provider request UUIDs. Requests outside the expected model, project binding, reference or timing trigger review. More than one request per single-use lease triggers review. Completed UTC-day aggregate spend is compared with reconciled costs. Alerts persist until an operator investigates; there is no customer-accessible alert reset. Records older than 30 days require historical review before Soniox's 91-day retention boundary. No guessed debit or automatic reservation release is substituted.

## Enforcement limits and release decision

Soniox documents service scoping, single use, admission expiry and a maximum **connection** duration. Its public contract reviewed here does not establish per-key model/configuration locks, revocation, an input-audio-duration ceiling, or a dollar ceiling. A modified client can alter the first configuration frame or potentially send accelerated audio. The normal desktop limits PCM duration and queue size, but client controls cannot enforce a hostile-client quota. Beta account allowlisting, short issuance, project separation, funded reservations, daily spend comparison and sticky anomaly alerts reduce exposure; they do not solve strict cost or concurrency enforcement.

Provider project spending/concurrency safeguards and accelerated-input behavior must be verified in the actual dedicated project before live beta exposure. No such external configuration or accelerated provider test has been performed yet. Public paid admission remains disabled regardless of payment confirmation. A minimal metered relay would keep the provider socket server-side, validate configuration, rate-limit PCM to real time, and meter accepted frames under a single lease. It would add a network hop and server access to sensitive audio; it needs explicit privacy/architecture approval and measured latency. This build does not silently introduce that relay.

## Run and verify

Apply both migrations to the designated staging database. Use a protected ignored `server/.env.staging` file and `node --env-file=server/.env.staging --import tsx server/main.ts`. Keep production sales evidence blank. Run `npm run server:check`, `npm run managed:check`, `npm test`, `npm run test:ui` and `npm run diagnostics:capture`. A local HTTPS tunnel can expose staging only for the supervised test; stop it after testing.

Hosted OTP, cross-account RLS/auth, real provider settlement, real sandbox checkout/webhook, physical headset/Mac behavior and a long live session require separate evidence. PGlite and synthetic screenshots do not prove those outcomes.
